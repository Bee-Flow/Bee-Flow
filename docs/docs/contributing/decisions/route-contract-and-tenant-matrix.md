# 0012: Every route declares its gate; tenant isolation is tested by matrix

**Status:** accepted, in effect. **Enforced by:** `server/routes.contract.test.js`
(`server/auth/routes.contract.json`, `npm run gen:routes-contract`),
`server/tenantIsolation.matrix.test.js` (`server/testUtils/tenantFixtures.js`,
`server/tenantIsolation.exemptions.json`, `lint:tenant-matrix-ratchet`),
`server/auth/loginPaths.inventory.test.js`, `server/auth/sessionShape.test.js`, the
`bare-fetch`, `static-mount`, `multer-guard`, `env-parseint-fallback`, `secret-equality` and
`instance-config-gate` ratchets, and `.semgrep/security-gates.yml` in `sast.yml`.

## Context

A per-route authorisation test proves one route. It does not notice the route next to it that
was added without one, the gate that moved from a platform role to an organisation permission,
the login path that skips the second factor, or the session key that now carries a secret.
`auth/accessRegistry.js` and its drift and sweep tests already prove that every route is
*accounted for* (a gate somewhere, a declaration, or an exemption with a reason). Accounted for
is not the same as unchanged: a route can keep a gate and still let more callers through.

## Decision

- **Gate class.** The router walk that generates the API reference also classifies every route
  by the strongest gate in its chain (`auth/routeContract.js`: platform, permission, scope,
  scoped, auth, middleware, handler, open). The classes are recorded in
  `auth/routes.contract.json`; a route that is missing there, or whose observed class is weaker
  than recorded, fails the server suite. The file is regenerated by hand and reviewed in the
  diff: a line whose class went down is the change to read. The open routes keep their reason
  in `auth/openRoutes.js`, one list for the sweep test and the contract.
- **Tenant matrix.** One fixture per resource kind creates a resource in organisation B and calls
  every listed route as a member of organisation A; 403 or 404 is the only acceptable answer,
  and the owner must get 200 so a kind that refuses everyone cannot pass. Routes with a path
  parameter that no kind drives are listed with a reason in `tenantIsolation.exemptions.json`,
  and that list is a ratchet.
- **Inventories.** Every call site of `establishSession` says what it does about MFA
  (`auth/loginPaths.inventory.json`), and every key written to the session is declared
  (`auth/sessionShape.json`); a new login path or session key fails until it is declared.
- **Boundary shapes.** A global `fetch`, an `express.static` without headers, a `multer` without
  the upload guard, a `parseInt(process.env.X) || n`, a `===` on a secret and an instance-wide
  config write without a platform gate are count ratchets locally and semgrep rules on pull
  requests.

## Consequences

- A new route, login path, session key or outbound call cannot land silently: each has a file to
  touch and a reviewer reads that diff.
- The contract and the matrix cost a router walk and a PGlite run per server test run, a few
  seconds each.
- The matrix proves isolation only for the kinds it drives; growing it is the work the
  exemption ratchet points at, one kind at a time.
- Like every ratchet (0002), the counts start at today's number and may only go down.
