# Slice W1: the web ratchet, the exact classification, the core tree

Scripts only (`scripts/`, `agent-hub/.module-boundary-ratchet.json`, the handoff lists). No change
under `agent-hub/src`. Read `DESIGN.md` ("Core mode, the ratchet, CI" and the edge kinds) and
`README.md` beside this file; `scripts/module-boundary.mjs` and its test are the server ratchet
you extend; `scripts/README.md` says what a script needs (header comment, a sibling test,
`npm run gen:scripts-index`, an entry in `scripts/roots-inventory.json`).

1. **`node scripts/module-boundary.mjs --pkg agent-hub`**: the same ratchet for the web client,
   with four metrics per module: static imports core -> module, lazy imports (`import()`),
   generated i18n chunk imports (`src/i18n/enNamespaces.ts`), and type-only imports
   (`import type`, and `typeof import()`), which `scripts/module-map-edges.mjs` leaves out
   today. Budget in `agent-hub/.module-boundary-ratchet.json` at today's numbers (the map says
   173 static in 108 files, 196 lazy of which 144 are the i18n chunks; count the type-only
   ones), `--update` only lowers, `--list` prints file:line. It joins `check:fast` by being a
   `lint:*` script in the root `package.json` (see how `lint:module-boundary-ratchet` is declared).
   Also: an import from module A into module B needs B in A's `requires` or `uses` (the web map
   has 12 undeclared today: list them in your report, budget them, do not edit the map).
2. **The exact classification**: `.claude/handoff/core-modules/web/static-edges.md`, generated by
   a script you keep (`scripts/web-edge-kinds.mjs`): every static core -> module import, its
   file:line, the imported names, and its kind (component rendered in JSX; hook `use*`; function
   or constant; a type that the scanner counted as a value; a row or lazy target in a shell
   list; a provider or overlay; an API or query module under `src/api`), decided from the
   syntax tree of the importing file, never by a regular expression over the text. Group it by
   the slices of DESIGN.md (hub and chat; studio and agents; admin and organisation; settings;
   shell, sidebar and demo; documents) by path, so each later worker has its list.
3. **The leaf candidates**: for every module-owned file that a core file imports statically,
   say whether it is a leaf: no import of another module-owned file (transitively), no call of
   an API path under a module's routes, no i18n key of a module's namespace
   (`server/i18n/defaults/en/<namespace>.js` owned by a module). Output a table in the same
   handoff file: file, importers, leaf yes/no and why not. The driver decides the re-ownership
   from it; do not edit `scripts/module-map.json`.
4. **`scripts/web-tree.mjs --mode core --out <dir>`**: materialise the core tree: copy the
   core-owned files of `agent-hub/` at their paths (sources, tests, configs, `index.html`, the
   public assets), link `node_modules`, and regenerate what is generated per present namespace.
   `--mode full` must give a tree whose `vite build` module list equals the in-place one. Then
   run, in the core tree, `npx vite build` and `npx tsc --noEmit` (memory: one at a time, retry
   when killed) and record the errors as they are today in
   `.claude/handoff/core-modules/web/core-tree-errors.txt` (file, first error): that list is the
   work of the later slices and may only shrink.
5. **`scripts/module-files-untouched.mjs --base <ref>`**: every module-owned file of agent-hub has
   the same content hash at its tree path as at `<ref>`, except the area files
   `src/firstParty/**`; prints the ones that differ. With a test.

Gates: `npm run test:scripts`, `npm run check:fast`, `npm run lint:scripts-index`,
`node scripts/roots-inventory.mjs --check`, eslint on your files. Report the numbers each
script printed.
