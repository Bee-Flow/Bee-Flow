# Review BUG #220 (Opus, read-only)

Commit ff8d0c735 "fix(cms): cms_update_design accepts numeric strings and reports numeric enums accurately".
Tests: `node --test cmsBuilder/builderTools.test.js` 34/34.

## Verdict: APPROVE

- The coercion applies only when every allowed value is a number. Mixed or string enums are
  unchanged.
- The regex `^\s*\d+\s*$` accepts only whole non-negative numbers. `Number(v)` is compared with
  `includes` against the closed list, so nothing outside the enum is stored. The stored value is
  the coerced number, which `sanitizeDesign`'s `numClamp` (typeof number) accepts, as the test
  confirms.
- The error message now prints the allowed values with `JSON.stringify` and says when a number
  is expected. String enums are quoted.
- Nothing unvalidated is persisted: an unknown field or value returns `bad(...)` before any write.
