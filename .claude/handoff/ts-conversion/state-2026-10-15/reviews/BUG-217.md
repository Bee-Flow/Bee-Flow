## Review of ce79fdcaf (Opus, read-only, late round)

Verdict: CHANGES REQUIRED.

1. REQUIRED (medium): `server/core/documents/documentContract.js:153` `coerceNumber`. The pattern `^-?\d+(?:[.,]\d+)?$` reads any single separator as a decimal point, so a thousands separator silently becomes a wrong number while the document stays valid. I checked: "1,000" fills as 1, "12,345" as 12.345, and "1.000" (one thousand in nl) as 1. In a quote or invoice that is a wrong amount with no warning. Fix: accept a comma as the decimal separator only when it is not followed by exactly three digits. Refuse the ambiguous form `^-?\d{1,3}[.,]\d{3}$` (and anything with two separators) with a clear message, for example `<key> must be a number without a thousands separator, got "..."`. Add a test for "1,000" and "1.000".
2. Minor: `documentContract.js:165` coerces list fields IN PLACE on the item objects. `setPath(values, key, value)` stores the supplied array by reference, so the caller's (and a list default's) objects are changed. Copy the items (`value.map(i => ({ ...i }))`) and set the copy back.
3. Minor: the builder change (`documentSteps.js:86-88`: no "prints blank" note when the parameter has a default) has no test. Add one to `automation/builderTools.fillDocument.test.js`.
