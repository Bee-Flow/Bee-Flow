### Verdict

**3912c69d0**: CHANGES REQUIRED (findings 1-3).

### What was checked and is fine

- **No style bypass.** `applyAddBlocks` (`server/cmsBuilder/builderTools.js:405-414`) runs
  `entry.style` through the same `validateStylePatch` (`cmsBuilder/blockStyle.js`) that
  `cms_update_block` uses (`builderTools.js:472`). The closed key set, the enums, the
  colour-token allow-list and the numeric spacing all apply. An invalid value drops only that
  entry, with the validator's message. The new block starts from `{}`, so there is nothing to
  merge, and the result matches what `update_block` would store on a fresh block. Persistence
  goes through the same `persistPage` path.
- **Scoped validation hides nothing that blocks publishing.** `scopeValidation`
  (`server/cms/mcp/siteContext.js:18`) passes `errors` through untouched. It only folds
  `empty_page` *warnings* for pages the call did not touch, and only when there are two or more;
  every other warning stays. `cms_publish` (`publishHandlers.js:22`) and `cms_list_site`
  (`siteHandlers.js:67`) still call `validationOf` without a scope, so publishing sees the full
  site-wide validation. `touchedPageIds` is a fresh `Set` per MCP call (`loadDraft`), so the
  scope is exactly this call.
- **Go-live homepage note**: it reads the draft the agent edits, reports `pageId`/`slug`/`empty`,
  and only on `goLive`. The page title it echoes belongs to the caller's own site.
- **Showcase empty media**: it collapses on the published site and keeps the placeholder under
  `?preview`, which matches media-text (`MediaText.tsx:96-97`). Issue item 6 was indeed already
  handled.

### REQUIRED

1. **MEDIUM: the seeded cookie text still disagrees between languages, in the other direction.**
   The NL seed is now neutral, but the EN seed still claims cookies are used
   (`server/i18n/defaults/cmsDefaults.js:84`, mirrored in `blockData.generated.mjs:85`). The
   renderer's built-in fallback still carries the old NL claim
   (`agent-hub/src/marketing/components/CookieBanner.jsx:33`). A site whose stored blob lacks
   `nl.message` therefore still shows the old sentence. The issue's rule is that "a seeded
   default should not make a claim". Fix: use one neutral sentence in both languages in all
   three places (for example "Cookie settings: choose what you allow." /
   "Cookie-instellingen: kies wat je toestaat."), regenerate `blockData.generated.mjs`, and add a
   test that the EN and NL seeds and the `DEFAULT_TEXT` fallback agree.
2. **LOW: the all-dropped error names the wrong cause.** `builderTools.js:420`: when every entry
   is dropped for `invalid-style`, the error still says the entries "had unknown or missing
   types" and attaches `typesHint()`. Fix: build the message from the `dropped` reasons (or say
   "unknown/missing type or invalid style"), and give the style `_fixHint` when that is the only
   reason. Add a case to `addBlocksStyle.test.js` with one entry that has a bad style.
3. **LOW: go-live can report failure after it has succeeded.** `publishHandlers.js:75` awaits
   `homepageReport` after the live switch and the audit. If `loadDraft` throws there, the agent
   gets an error for a call that did take effect, and may retry it. Fix: wrap the report in
   try/catch and fall back to `homepage: null` (log the failure with `log.warn`).

### Not required

- `validateStylePatch` messages say `stylePatch.<key>`. In an add call the field is
  `blocks[i].style`. The `index` in `dropped` makes it findable, but a prefix would be clearer.
- Showcase `pair`/`code-ui` with a single missing image leaves its grid column empty on the
  published site. That is out of scope of the issue.
