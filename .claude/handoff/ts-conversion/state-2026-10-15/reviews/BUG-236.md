# Review BUG #236 (Opus, read-only)

Commit 667d5d180 in `Bee-Flow-wt/bug-C6`, "fix(cms): cache uploaded assets for a year, serve resized
WebP variants and pre-compressed JS/CSS".
Tests: `node --test routes/cmsAssets.test.js` 29/29, `node --test boot/brotliStatic.test.js` 2/2,
`vitest run src/marketing/assetUrl.test.ts` 2/2. `npm run typecheck` (server): 1102 `// @typecheck`
files, no errors. The new server files carry `// @typecheck`; the agent-hub code is TS;
`precompress.mjs` is a build script with JSDoc.

## Verdict: CHANGES REQUIRED

The general direction is right: a year of cache for minted upload keys, a 304 without a storage
read, fixed widths for the variants (so the query string cannot create unbounded variants), srcset
only for uploaded raster images, and gzip_static at level 9. The asset route keeps the same auth
and scoping: it was public before and still is, the `cms/` prefix check is unchanged, and the
admin list and upload routes are untouched. Errors (404, 416) carry no cache headers.

The blocker is the premise "keys are never overwritten". That is true for uploads, but some
`cms/` keys are overwritten on purpose.

## REQUIRED

1. **HIGH: `immutable` and a key-only ETag are applied to keys that do get overwritten.**
   `server/routes/cmsAssets.js:149-161`. The site seeder writes stable keys
   (`cms/beeflow-logo.svg`, `-favicon.svg`, `-hive.svg`, `-architecture.svg`, ...,
   `cms/beeflow-<screenshot>.png`, see `server/scripts/content/beeflowAssets.js:292-297,344`) with
   `restoreAssets(..., { overwrite: true })` (`server/scripts/seedBeeflowSite.js:102`). The header
   comment of `restoreAssets` says it exists precisely so that a re-seed CHANGES those bytes. With
   this commit, a browser or CDN keeps the old logo for up to a year. Because the ETag is just the
   key and the 304 is answered without reading storage, even a forced revalidation never sees the
   new bytes.
   Fix: send `immutable` only for keys in the minted upload shape. Both uploaders and the MCP
   receiver produce `cms/<13-digit ms>-<random>-<name>`, so match e.g.
   `^cms\/\d{13}-[0-9a-z]+-`. Every other key keeps a short `max-age` (the old 3600, or `no-cache`)
   with an ETag taken from the object (storage ETag or a content hash) and a 304 decided on that
   ETag. Add a test with a seeded key that is overwritten.

2. **MEDIUM: variant rendering on a public route has no resource bounds.**
   `server/core/cms/assetVariants.js:65-75`, `server/routes/cmsAssets.js:184-189`. Anyone can
   trigger the variant path without signing in. Each cache miss buffers the whole original (up to
   25 MB) and decodes it twice (`metadata()`, then the resize) with sharp's default pixel limit
   (about 268 megapixels, i.e. gigabytes of decode memory for a highly compressible image). Renders
   have no concurrency cap and no in-flight dedupe. A result that is null (animated, unreadable, or
   "not smaller than the original") is never cached, so every request for it decodes again. The
   pixels are not only from trusted admins: an imported site bundle is treated as untrusted input
   elsewhere (`core/cms/cmsExportBundle.js`).
   Fix:
   - pass `{ limitInputPixels: <~40e6>, failOn: 'error' }` to both `sharp()` calls;
   - read `meta.width`/`height` first, and serve the original without decoding when the image is
     already no wider than `w`;
   - cache negative results (a small marker entry in the same LRU);
   - add a per-key in-flight promise map and a small semaphore (1-2 concurrent renders, then
     answer with the original);
   - skip the variant path when `contentLength` is above a cap.
   Add a test for the oversized-input case.

3. **LOW: the ETag is built from the raw key.** `server/routes/cmsAssets.js:153`. A key with a
   `"` gives a malformed ETag. A character outside the header-safe range makes `setHeader` throw,
   so a request that used to get 404 now gets 500. Uploaded keys are sanitized, but bundle-imported
   keys and request paths are not. Fix: use an opaque ETag (a hash of key and width, or the
   object-derived ETag from finding 1). While you are there, accept an `If-None-Match` list and a
   `W/` prefix.

## Recommended (not blocking)

4. MCP upload receiver, fixed key per ticket (`server/cms/mcp/uploadReceiver.js:252-254`). A
   ticket is handed back only when nothing was stored, and the asset URL is returned only on
   success, so in normal flows no immutable URL is overwritten. The remaining window is ambiguous:
   the storage call fails after the object was actually committed (a lost response, or a multipart
   complete that succeeded server-side). The retry can then write different bytes under a key that
   is already listed in the asset library and `cms_list_assets`. Suggest: on a retry, `headFile`
   the bound key and mint a fresh key if an object exists.
5. `cmsAssets.js:183`: the cache headers are set before the variant body is buffered. A storage
   or stream error after that point answers 500 with `public, max-age=31536000, immutable`. Set
   them just before a successful body is written.
6. `?w=` together with a `Range` header serves a range of the ORIGINAL with the variant's ETag
   (`-w640`). Ignore `Range` when a width is set, or give the fallback its own ETag.
7. Brotli (`server/boot/brotliStatic.js`).
   What is correct: path traversal is guarded (`decodeURIComponent` failures fall through,
   `path.resolve` plus a root-prefix check). Only an existing `.br` sibling inside the static root
   is served. The Content-Type is set before `send`, which keeps it. `Content-Encoding: br` and
   `Vary` are set. HEAD and GET only.
   What does not hold: in the shipped images this middleware never runs. The server image is
   built from `server/` only and has no `agent-hub/dist`, and nginx serves the SPA in every stack.
   So the `.br` files only add weight to the nginx image. Either drop `.br` generation there, or
   document it as "Node-served SPA only" and correct the commit message. Minor: `\bbr\b` also
   matches `br;q=0`.
8. srcset: the descriptors always list 1280w and 1920w, even for an original that is narrower.
   The server never enlarges, so the browser computes the wrong density, which matters when the
   CSS does not fix the width. `sizes` is `1200px` for the half-width MediaText column too, which
   over-fetches. Consider passing the stored width (`media.width`) to `assetSrcSet` and capping
   the list at it.
