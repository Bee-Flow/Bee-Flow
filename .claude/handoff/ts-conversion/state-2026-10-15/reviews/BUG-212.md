# Review BUG #212 (Opus, read-only)

Verdict on dfc59defb: CHANGES REQUIRED.

Findings:
1. Medium (required), server/automation/mcpDocumentReads.js:35-39 (`restore`): a contract read up to 30 minutes
   ago is restored even when the document has a newer version since. `inspectBindings` then pins
   `documentVersionId` to the old contract's version and checks the bindings against the old parameters, so a
   step can be saved silently against an outdated revision. In the chat this window was one turn; this commit
   makes it 30 minutes. Fix: `restore` runs after `_documents` is loaded, so keep a restored contract only when
   the fresh catalog has that document with the same `versionId`; drop it otherwise (the caller then gets the
   normal "read it first" error). Add a test where the catalog's versionId changes between read and add.
2. Low, mcpDocumentReads.js:50: `reads.set` on an existing key keeps its original insertion position, so the
   MAX_ENTRIES eviction removes the oldest-created entry, not the least recently used one. Fix: `reads.delete(key)`
   before `reads.set`.
3. Low, documentation: the store is per process. With more than one server replica (no replica config in this
   repo) the read and the add can land on different processes and the bug returns intermittently; a restart also
   drops it (owner's follow-up comment). State this in the module header; the owner's suggestion (accept the
   `documentVersionId` already pinned on an existing step in builder_update_step) is a reasonable follow-up, not
   required here.

Checked and fine: key is (userId, automationId) from `loadDraft`, which first refuses an automation the token's
user does not own; nothing persists to the database; TTL is checked on restore and swept on remember; entry count
capped at 500 (contracts hold the document contract, not the body). Access is still re-checked per call: the
document catalog is re-read in `loadDraft` and `applyAddFillDocument` refuses an id not in it, so a revoked
document cannot be used via a cached read. The contract check itself is unchanged. Tests cover cross-call success,
another automation, another user (refused at ownership) and TTL expiry:
`node --test automation/mcpBuilder.fillDocument.test.js` 3/3.
