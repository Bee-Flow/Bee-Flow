### REQUIRED

1. **HIGH: the App Studio runtime bundle puts `utilities` below `base`, so preflight beats the
   utilities.** `agent-hub/vite.runtime.config.js:42` *prepends*
   `import '@/tailwind-utilities.css'` to the module that imports `index.css`. The utilities
   stylesheet is therefore emitted first, and it declares its layers before index.css's order
   statement (`agent-hub/src/index.css:13`) is reached. The built `app-runtime.css` has the
   order `properties, theme, utilities, base, components`. Preflight (`*{margin:0;padding:0;
   border:0 solid}`) and anything in `components` now override every padding, margin and border
   utility, and a few others. That bundle is what `server/services/appStudioRender.js` uses to
   screenshot App Studio screens for the builder AI, so the AI sees broken layouts. The commit
   message says "appends", the code prepends. Fix: open `tailwind-utilities.css` with the full
   order statement `@layer properties, theme, base, components, utilities;`. That makes it
   correct whichever file loads first. Moving the injected import after the code would also work,
   but the order statement is the robust fix. Test: a build check (or a test over the built
   runtime CSS) asserting that the first layer order puts `utilities` last among
   theme/base/components/utilities.

2. **MEDIUM: in the SPA, the deferred stylesheet adds the `properties` layer last, above
   `utilities`.** `index.css` declares `theme, base, components, utilities`. `properties` first
   appears in `tailwind-utilities-*.css`, so it is appended after `utilities` and wins over it.
   Its rules sit inside Tailwind's `@supports` fallback for browsers without `@property`
   (older Safari, Firefox before 128). On those browsers, the `*{--tw-translate-x:0;
   --tw-shadow:...}` defaults override utility-set `--tw-*` values, which breaks transforms,
   shadows, rings and gradients across the app. Before the split, `properties` came first. Fix:
   `agent-hub/src/index.css:13` must read `@layer properties, theme, base, components,
   utilities;` (and the same line as in finding 1 at the top of `tailwind-utilities.css`). Verify
   in the built `index-*.css` that the statement survives minification.

3. **MEDIUM: the budget gate passes when the budget file is missing.**
   `scripts/entry-budget.mjs:105` `if (update || !existing)` writes a fresh budget at
   measurement +3% and exits 0. In CI, a deleted or renamed `.entry-budget.json` (or a typo in
   the package argument) is therefore a silent pass at whatever size the build has, which is the
   "a build that did not happen is not a pass" case the script already guards for `dist/`. Fix:
   without `--update`, a missing budget file exits 2 with a message saying to create it with
   `--update`. Only `--update` may create it. Add a test.

4. **MEDIUM: "Fixes #245" closes an issue that is only partly done.** Both commits carry
   `Fixes #245`. The issue's CSS target is under 25 KB gzipped render-blocking, and this lands at
   32.9 KB. The budget also leaves out "requests before LCP", and the image, font, entry-JS and
   CMS-warning items are still open. Fix: reword both commits to `Refs #245` (or `Part of
   #245`), and list in the PR body which checklist items this covers.

5. **LOW: above-the-fold icons change size when the deferred utilities arrive (small layout
   shift).** Marketing still relies on utility classes for icon size: `w-4 h-4` in
   `sections/Hero.jsx:93` (hero badge), `components/LanguageSwitcher.jsx:83` (header) and
   `components/CookieBanner.jsx:116`, and `w-5 h-5` / `w-6 h-6` elsewhere. Registry icons are
   Lucide SVGs with `width="24" height="24"`, so until idle (up to 3 s) they render at 24 px and
   then shrink to 16 px. The hero badge pill gets a few pixels shorter and the hero below it moves
   up. That is a CLS contribution with no user input, on the page the change is meant to speed
   up. Icons inside a fixed `.icon-tile` stay inside their tile. Fix: give the marketing icons an
   explicit `size={16|20|24}` (or size rules in `marketing.css`) so they do not depend on the
   utilities layer. Also correct the comment at `index.css:9`: no chunk imports the utilities
   file; only `main.tsx` does.

6. **LOW: LazyLoopVideo with reduced motion shows an empty box, and the box can resize on
   scroll.** `LazyLoopVideo.tsx:66,73`: with reduced motion, `src` is set but `preload="none"`,
   and no call site (FramedMedia, MediaText, Content) passes a `poster`. The browser therefore
   shows neither a poster nor a first frame, only a blank player with controls. The comments at
   `:13` and `:71` ("poster frame (or the first frame)", "only the metadata is fetched") are wrong
   for `preload="none"`. Fix: with reduced motion and no poster, use `preload="metadata"` (one
   request, on a reduced-motion pageview only), or pass the block's poster where one exists, and
   correct both comments. The resize: FramedMedia (`.cms-frame-media { width:100%; height:auto }`)
   and MediaText give the video no aspect ratio. A video with no `src` lays out at the default
   300x150 and only takes its real ratio once the metadata arrives. With lazy attach that now
   happens during the scroll and no longer at load. Fix: reserve the box (pass the intrinsic
   `width`/`height` when the block has them, or default to `aspect-ratio: 16/9` on
   `.cms-frame-media` video and the MediaText video). Content.tsx already wraps the video in an
   `aspect-ratio` box.

7. **LOW: units in the budget output.** `kb()` divides by 1024 but prints `kB`, while the commit
   message and JSON comment use decimal KB ("337.5 KB" is 337,526 B). Print `KiB`, or divide by
   1000, so a budget message matches what the commit text says.

### Checked and fine
