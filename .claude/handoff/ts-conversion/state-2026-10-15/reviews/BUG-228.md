## Verdict: CHANGES REQUIRED

1. **Links inside locale overrides are not neutralised** - `server/stores/cms/pageRemoval.js:86-99`,
   severity medium. Only base `doc.blocks` of the remaining pages and the base header/footer are
   cleaned. Page-level overrides (`pagesByLocale[...].blocks`) and site-level overrides
   (`siteByLocale[...].header/footer`) can hold page links too (the #227 export annotates exactly
   those), so a translated page or translated nav keeps publishing the dead link and
   `neutralisedLinks` under-counts. Fix: the `collectLocaleOverrides(siteId, { fresh: true })` call
   is already there; run `neutralisePageLinks` over each site override's header/footer (in the same
   write that prunes `pageTitles`) and over each remaining page's override blocks, and add a test.
2. **Read-modify-write of other pages uses the cached read** - `pageRemoval.js:87`, severity low.
   `getPage(siteId, id)` can return this replica's cached copy (up to 60 s old) and `setPage` then
   writes it back, which can undo an edit another replica saved moments earlier. The admin read path
   already uses `{ fresh: true }` for this reason. Fix: `getPage(siteId, id, { fresh: true })`.
