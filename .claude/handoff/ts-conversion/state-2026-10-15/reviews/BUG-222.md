# Review BUG #222 (Opus, read-only)

Commit 9b980edc8 "fix(cms): cms_update_block persists the style v2 keys its description documents".
Tests: `node --test cmsBuilder/builderTools.test.js` 34/34 (includes the two new tests).

## Verdict: APPROVE

- The new keys are each validated against a closed whitelist: `band`
  default|surface|tint|dark|primary, `rhythm` compact|default|spacious, `reveal` on|off,
  `glow` strict boolean, `columns` 2|3|4 (a whole-number string is coerced, then checked with
  `includes`).
- An invalid value rejects the whole call before `persistPage`. The test checks that a rejected
  patch changes nothing. Unknown keys are dropped with a hint, and only validated keys reach
  `mergedStyle`.
- The values match the renderer (`agent-hub/src/marketing/ProductWebsite.jsx`
  `blockWrapClasses` / `blockWrapStyle`). That code builds class names only from its own
  hard-coded arrays and sets `--cms-cols` only for `[2,3,4].includes(Number(...))`, so none of
  the new keys can carry markup or CSS.
- The drift test pulls the key list out of the `cms_update_block` description and compares it
  with `STYLE_KEYS`. If the anchor phrase changes, the `split(...)[1]` returns `undefined` and
  the test throws, so it fails loudly rather than passing vacuously.
- `blockStyle.js` is a verbatim move of the v1 validator plus the new branches. The behaviour of
  the v1 keys is unchanged.
