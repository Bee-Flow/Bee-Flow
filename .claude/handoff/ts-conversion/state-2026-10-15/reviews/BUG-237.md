### Findings

1. **REQUIRED, low.** `renderBlocks.js:202-210` (`collectLinks`) checks `enabled !== false` only on
   the link node itself and keeps recursing through everything else. A switched-off
   header or footer (`header.enabled` / `footer.enabled`, `cmsDefaults.js:30`, `:61`) or a disabled
   group still contributes its links to the server-rendered nav, so the no-JS HTML lists
   links the visitor never sees. Fix: return early when `node.enabled === false`, before
   recording or recursing; add a test with `footer: { enabled: false, ... }`.
2. Optional, low. The own-origin test (`startsWith('/') && !startsWith('//')`) is now written
   three times (`imageSrc`, `internalHref`, and the existing `internalCtaHref`). It is not an
   XSS issue (all output is escaped, values are admin-authored), but a single helper that
   resolves the value with `new URL(value, base)` and compares the origin would be stricter
   about the forms browsers normalise, and keeps the three in step.
3. Optional, low. Header CTAs such as the default `/app` "Get started" now land in the
   crawler nav. Consider leaving out paths `parsePublicPath` does not accept as marketing
   pages.

### What holds

- Every new interpolation goes through `esc`: `<img src>` and `alt`, the card anchor's
  `href` and text, and each nav `href` and label. `esc` covers `& < > " '`, all attributes are
  double-quoted. The alt-escape test covers the attribute case.
- `imageSrc` accepts only `cms/` keys (encoded per segment, the same URL the admin
  `ImageField` builds), `http(s)` URLs and single-slash absolute paths; other schemes give no
  tag. Non-image media (`kind` other than `image`) are skipped.
- Card anchors and nav links are own-origin only; external, protocol-relative and `#` links
  are left out (tested). Nav links are de-duplicated per address.
- Removing `media` from `SKIP_KEYS` adds no stray text: `alt`, `src`, `srcDark`, `frame` and
  `kind` are not prose keys or are skipped.
