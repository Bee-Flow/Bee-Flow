### What holds

- `@shell_not_found` carries exactly the same `add_header` set as `@shell` (Cache-Control,
  nosniff, X-Frame-Options, X-XSS-Protection, Referrer-Policy, Permissions-Policy, the same
  `$csp`); confirmed on the live response. No value from the request reaches a header.
- `if (...) { return 404; }` is the safe form of `if` inside a location.
- The blog's not-found path and the page not-found path share one helper; 410 is only for
  slugs on the (empty) `GONE_SLUGS` list.

### Notes (no change required)

- Deploy order: server and agent-hub images must ship in the same release. A new server
  behind an old nginx turns these answers into 200 shells (a soft 404, worse than the old
  410) until nginx is updated; an old server behind the new nginx is harmless.
- The 404 body is nginx's static shell, not the renderer's `noindex` variant; fine for a 404.
- On a 410 the marker header reaches the client. Harmless; `proxy_hide_header` in `@render`
  would hide it if wanted.
